# Integração — i18n (pt-BR / en / es) e tema claro/escuro

Bibliotecas prontas, sem dependências. Arquivos de propriedade deste módulo:

| Arquivo | Papel |
| --- | --- |
| `src/web/lib/i18n.js` | motor de tradução, cascata, aplicação por atributos |
| `src/web/lib/theme.js` | controle de tema `light` / `dark` / `auto` |
| `public/theme.css` | tokens de tema e acessibilidade |
| `public/locales/{pt-BR,en,es}.json` | catálogos (148 chaves, paridade total) |

---

## 1. CSS

No `<head>` de `public/index.html`, **depois** de `/styles.css`:

```html
<link rel="stylesheet" href="/styles.css">
<link rel="stylesheet" href="/theme.css">
```

Para evitar flash de tema errado, rode o tema antes da primeira pintura:

```html
<script type="module">
  import { applyThemeEarly } from '/src/web/lib/theme.js';
  applyThemeEarly();
</script>
```

## 2. Tema

```js
import { createTheme } from './lib/theme.js';

const theme = createTheme();               // lê localStorage('theme'), aplica data-theme no <html>

const btn = document.querySelector('#theme-toggle');
btn?.addEventListener('click', () => {
  const { resolved } = theme.toggle();      // 'light' | 'dark'
  btn.setAttribute('aria-pressed', String(resolved === 'light'));
});

// rótulo acessível acompanha o tema efetivo
theme.follow(({ resolved }) => {
  const key = resolved === 'light' ? 'app.theme_dark' : 'app.theme_light';
  btn?.setAttribute('data-i18n-aria', key);
  i18n.apply(btn);                          // reaplica só no botão
});
```

`set('auto')` volta a seguir `prefers-color-scheme`. Use `theme.current` (`light|dark|auto`) para
marcar o item de menu correspondente, e `theme.resolved` para o que está na tela.

## 3. Seletor de idioma

```html
<select id="lang-select" aria-label="Idioma" data-i18n-aria="app.lang_aria">
  <option value="pt-BR" data-i18n="app.lang_pt">Português</option>
  <option value="en" data-i18n="app.lang_en">English</option>
  <option value="es" data-i18n="app.lang_es">Español</option>
</select>
```

O `select` é montado antes do boot (os `<option>` são fixos), então o texto das opções pode ser
traduzido direto pelo `i18n`:

```js
import { createI18n } from './lib/i18n.js';

const i18n = createI18n();                  // respeita localStorage('locale') e navigator.language
i18n.mount(document.body);                  // aplica + observa nós novos
document.querySelector('#lang-select').value = i18n.locale;
document.querySelector('#lang-select').addEventListener('change', (e) => {
  i18n.setLocale(e.target.value);
});
```

## 4. Marcação

| Atributo | Efeito |
| --- | --- |
| `data-i18n="chave"` | substitui `textContent` |
| `data-i18n-title="chave"` | substitui `title` |
| `data-i18n-aria="chave"` | substitui `aria-label` |
| `data-i18n-placeholder="chave"` | substitui `placeholder` |
| `data-i18n-vars='{"n":3}'` | variáveis da interpolação |

```html
<h2 id="map-title" data-i18n="map.title">Mapa por estado</h2>
<p class="hint" data-i18n="map.hint">Clique em um estado…</p>
<button id="btn-live" data-i18n="timeline.live" data-i18n-title="timeline.back_to_live">AO VIVO</button>
<span data-i18n="sections.of_total" data-i18n-vars='{"counted":120,"total":300}'></span>
```

### Valores dinâmicos

Elementos com número/data calculado em JS devem ser reaplicados após o `setLocale`. Prefira marcar
o texto-base e chamar `i18n.apply(el)` depois de cada render:

```js
function renderKpis(state) {
  els.kpiSections.dataset.i18nVars = JSON.stringify({
    counted: state.counted,
    total: state.total,
  });
  els.kpiSections.setAttribute('data-i18n', 'sections.of_total');
  i18n.apply(els.kpiSections);              // reaplica só a subárvore
}
```

Para strings compostas programaticamente use `i18n.t('kpi.ufs_sub', { total: 27 })`.
Nunca use `innerHTML`: o motor só escreve `textContent` e atributos.

## 5. Boot e re-render

No `boot()` de `src/web/app.js`, **antes** do primeiro `render`:

```js
i18n.mount(document.body);                  // aplica tudo que já existe
i18n.onChange(() => {
  document.title = i18n.t('app.title');
  render();                                 // re-renderiza dados derivados
});
document.title = i18n.t('app.title');
```

Componentes que criam DOM sob demanda devem chamar `i18n.apply(container)` no fim do próprio
`render` (o `MutationObserver` do `mount` cobre o caso, mas a chamada explícita garante ordem).

Ao trocar de idioma, o `<html lang>` e o `<html dir>` são atualizados automaticamente.

## 6. Mapa de chaves

- `app.*` cabeçalho, idioma, tema
- `conn.*` conexão, reconexão, offline
- `kpi.*` indicadores
- `map.*`, `panel.*`, `states.*` mapa e painel de UF
- `bars.*`, `markets.*` candidatos e mercados (`markets.disclaimer` = "probabilidade implícita, não é pesquisa")
- `timeline.*` replay, velocidades, fim do histórico
- `totals.*`, `sections.*`, `abroad.*` totais, seções apuradas, exterior
- `round.*` 1º/2º turno · `time.*`, `date.*` datas · `number.*` mi/mil
- `warn.*`, `error.*`, `empty.*`, `a11y.*`, `noscript.*`, `footer.*` (fonte TSE)

Substituições nos textos atuais: `kpi-sections-sub`, `kpi-votes-sub`, `kpi-ufs-sub`,
`partial-warning`, `conn-text`, `#status-text` e os itens do `#speed` devem perder o texto fixo e
passar a usar `data-i18n` (os valores de `speed` são `timeline.speed_value` com `{n}`).
